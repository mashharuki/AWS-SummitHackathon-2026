# Marp Slide Stylesheet Enhancement Requirements

## Intent Analysis

- **User request**: Improve the stylesheet used by Marp slides generated by the slide creation tool so the output looks more polished.
- **Request type**: Enhancement to an existing feature.
- **Scope estimate**: Single backend component, focused on `pkgs/backend/src/marp/MarpSlideService.ts`.
- **Complexity estimate**: Simple. The change is mostly prompt and CSS generation, with no API contract, storage, IAM, or authentication changes.
- **Brownfield context**: Existing Marp generation renders AI-produced Marp markdown with `@marp-team/marp-core`, wraps the rendered HTML in a full HTML document, uploads it to S3 when configured, and optionally posts the generated URL to Slack.

## Functional Requirements

- The generated Marp markdown should continue to be self-contained and render through the existing Marp pipeline.
- The generated slides should use a more intentional visual system than the current default theme:
  - strong cover and section slides,
  - high-contrast typography,
  - restrained accent colors,
  - better bullet hierarchy,
  - improved code block and table styling,
  - polished page numbers and slide framing.
- The HTML wrapper should apply a more premium preview page around rendered Marp output.
- The fallback fixture slide deck should also use the improved theme so the local/no-Bedrock path remains visually representative.
- Existing endpoints and MCP tools must continue to work:
  - `POST /api/marp/create-slides`
  - `POST /api/marp/create-slides-and-post-to-slack`
  - `saborou_create_marp_slides`
  - `saborou_create_marp_slides_and_post_to_slack`

## Non-Functional Requirements

- No new runtime dependency is required.
- No new AWS resource, IAM permission, S3 bucket, CloudFront distribution, or environment variable is required.
- Rendering must remain compatible with `@marp-team/marp-core`.
- Output HTML must remain portable as a single uploaded HTML object.
- User-supplied title text must remain escaped in the document title.
- The styling should avoid relying on external fonts or remote CSS, because the generated HTML is viewed from a signed S3 URL.

## Constraints

- Do not change request or response schemas.
- Do not change Slack posting behavior.
- Do not weaken existing authentication or approval checks.
- Do not add inline JavaScript.
- Do not introduce public access changes to the Marp slides bucket.

## User Stories Assessment

User Stories are skipped. This is a focused visual enhancement to an existing generated artifact, with one primary user-facing outcome and no new workflow, persona, API, or business rule.

## Acceptance Criteria

- Generated Marp markdown contains an embedded custom theme/style block or equivalent styling guidance.
- Rendered HTML includes improved page-level preview styling around Marp SVG output.
- Fixture output uses the same improved visual direction.
- Backend tests or targeted verification confirm `createSlides` can render a deck successfully without Bedrock.
- Existing schema and route behavior remain unchanged.
